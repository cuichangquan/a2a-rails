## How to interpret status

- **EVIDENCED:** the precisely stated claim has an existing test/operator record.
- **PARTIAL:** significant evidence exists, but one or more acceptance conditions remain; **release checkbox stays unchecked**.
- **OPEN:** no adequate evidence or independent sign-off yet; **release checkbox stays unchecked**.
- Negative tests with injected resolver/test CA/loopback policy and actual restricted public-HTTPS Client connectivity prove **different things**. Neither substitutes for the other.

### Distinct public/no-auth Cloud Run gate

The [Step 29-5e protected readiness runbook](step-29-5e-public-window-readiness.md) explicitly leaves its **public/no-auth Cloud Run scenario NOT RUN**. The completed **IAM-private** run provides genuine public destination DNS/CA/Client socket proof, but is not the same experiment. Never unprotect Cloud Run or provision GCP/runner/NAT/egress resources implicitly.

**Decision needed later:** either (a) the owner separately approves a narrowly controlled, billable, short no-auth window with a verified rollback and scoped runner, **or** (b) the team formally revises the distinct no-auth acceptance criterion with a documented technical/safety rationale and independent sign-off. Do not silently treat private IAM evidence as public/no-auth completion. This is a **governance gate**, not a reason to repeat expensive GCP work now.
