## Publish only the verified final-main bytes, after separate owner GO

1. Obtain separate authorization before merging. Verify the actual main commit,
   independent review and all required CI, including the **Build-once release
   candidate and exact-install matrix** workflow
   (`.github/workflows/v0.3-client-private-candidate.yml`) on that exact commit.
   Required install, advisory, PostgreSQL, queues and interoperability checks
   must pass; do not bypass checks or force-push.
2. Use only that final-main run's
   **a2a-rails-0.5.0-stable-candidate-ci-only** artifact. Packages from the other
   packaged Rails/PostgreSQL workflow and local builds are regression evidence,
   not upload inputs. Download into a fresh directory; verify `SOURCE_COMMIT`
   equals the verified main commit, `STAGING_DELTA` says
   `NONE: exact source, no staging edit`, and `sha256sum -c SHA256SUMS` passes.
   Verify the package name/version is `a2a-rails` / `0.5.0`. Record the run/artifact
   identity and Gem SHA256 (distinct from the artifact ZIP digest). Stop on mismatch.
3. Present the exact artifact, hash, source, passing checks and limitations to the
   owner for a distinct publication GO. Only then may the maintainer run
   `gem push ./a2a-rails-0.5.0.gem`, using their passkey when required. **Do not
   rebuild**. No workflow publishes, tags or creates a GitHub Release.
4. Fetch the public Gem into another directory and verify byte equality/SHA256
   against that uploaded artifact. If indexing is delayed, poll; **do not push
   again**. Record verified publication evidence only after it exists.
5. Tag and GitHub Release require their own explicit scope authorization and must
   refer to the verified source. Demo public-version pins and HTTP/TLS checks are
   separate follow-up work after publication. Deployment is not implied.
