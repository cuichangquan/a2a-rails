## Compatibility fix and verification

0.5.1 adds a temporary distributed runtime dependency bound
`regexp_parser ~> 2.0, < 2.13.2`. The published SDK/schema dependency chain fails
with parser 2.13.2 because its `implements` class method became private. Fresh
0.5.1 installs select the known-compatible 2.13.1, while previously compatible
lower 2.x lockfiles remain allowed. No public API, protocol, persistence or
Handler behavior changed; no global monkey patch was introduced.

The canonical exact-installed matrix reproduced the precise 0.5.0 / parser
2.13.2 failure, then verified that the same 0.5.1 artifact resolves 2.13.1 without
a host parser pin and passes SDK loading, JSON Schema validation and public
result checks. Existing Ruby/Rails, installed HTTP/authentication, PostgreSQL,
queue, advisory and official Python/Go interoperability gates were retained.
See the [historical preparation and removal criteria](v0.5.1-preparation.md)
before relaxing the temporary upper bound after an upstream fix.

The informational pinned TCK remains partial: **63 passed / 1 known failure /
171 skipped / 30 deselected** ([upstream CORE-SEND-003](https://github.com/a2aproject/a2a-tck/issues/202)).
Workflow success is not full A2A conformance. Existing async and continuation
recovery limits remain; see the [continuation guide](../guides/task-continuation.md)
and [upgrade/recovery guide](upgrading-v0.4.0-to-v0.5.md).
