## What's new since v0.1.0

- **Rails host security boundaries:** configurable request authentication, fail-closed production defaults, owner-scoped Task access, guarded Agent Card security metadata, and request-size/defensive input limits.
- **Optional durable Task Store:** `ActiveRecordStore` with owner scoping, transactional lifecycle transitions, PostgreSQL locking, pagination, retention/pruning and resource guards. The default `MemoryStore` remains process-local.
- **Opt-in background execution:** `ActiveJob` asynchronous Task execution, execution-claim-based duplicate suppression, queue handoff checks, and cancellation/late-completion safeguards. Separate-worker Solid Queue and Sidekiq HTTP smoke was exercised.
- **A2A response coverage:** direct Message responses and File Artifacts (bytes/HTTPS URL).
- **Interop and verification:** Ruby/Rails matrix, Rails 8.0/8.1 installed-Gem security checks, PostgreSQL smoke, Solid Queue/Sidekiq HTTP E2E, official Python/Go SDK interop and the pinned official A2A TCK profile.

## Compatibility

- Ruby **3.3+**; Rails **8.0 / 8.1**.
- A2A protocol **v1.0**, server-side **JSON-RPC** integration.
- Non-streaming; no bundled A2A client, OAuth provider, universal business authorization or distributed rate limiter.
- In production/staging, hosts must configure a verifier and matching Agent Card security settings; v0.1.0 integrations can require changes.

## Production caveat

**Open public production remains NO-GO by default.** Production deployment requires host-specific credential verification, business authorization, TLS/ingress limits, distributed rate/concurrency limits and monitoring. Async work additionally requires an explicitly selected durable Task Store and durable ActiveJob backend, plus business-side idempotency and recovery procedures. Follow [production checklist](https://github.com/cuichangquan/a2a-rails/blob/main/docs/release/security-hardening-release-checklist.md) and [Issue #11](https://github.com/cuichangquan/a2a-rails/issues/11).
