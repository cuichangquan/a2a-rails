## Decision: NO-GO for public release of v0.3.x

**This is a source/evidence-focused, maintainer-assisted internal review. It is NOT an independent security review or final release authorization.** The Client has substantial negative tests and real interoperability evidence, but the exact candidate distribution artifact, an independent security sign-off, and certain deliberately separate protocol/exposure criteria remain incomplete. Do not tag, create a GitHub Release, change Cloud Run IAM, create GCP resources or push to RubyGems in this step.

**TCK caveat:** Existing inbound official A2A TCK evidence includes a documented upstream/fixture failure and skipped/deselected cases. It is not full protocol-wide certification and should not be promoted to a blanket PASS. The outbound Client and inbound Server have different threat models.

### Specific decisions remaining

1. **P0 — Go SDK authenticated ListTasks:** Establish an explicitly authorized principal/test-only Go SDK authentication setup **without bypassing the SDK's access controls**. Run two real cursor pages through the ordinary Rails Client and demonstrate tenant isolation where supported. If the SDK cannot support the tested semantics, record an exact feature/SDK limitation and require owner plus reviewer sign-off on any narrower release criterion. Do not mark the row PASS on `-31401`.
2. **P0 — Source/artifact identity:** Choose a distinct `0.3.x` release-candidate version *in a separate authorized candidate-preparation PR*, freeze an exact source SHA, build **one** Gem artifact, compute SHA256, and install **that identical artifact** into isolated Rails 8.0/8.1 Ruby 3.3/3.4/4.0 integration hosts with Client-only mode, PostgreSQL and security/interop regressions. The existing v0.2.0 Gem/PG proof does not test the unreleased Client binary as a published-version artifact. Avoid reuse of the stable `0.2.0` identifier.
3. **P0 — Independent review:** Obtain documented human or independently accountable reviewer approval of the *exact* candidate code/diff: policy/URL/SSRF/DNS/socket binding; TLS trust and callback/log disclosure; request/response bounds; error taxonomy; idempotency and queued worker recovery; compatibility/breaking changes. Record reviewer, SHA, explicit accepted risks and unresolved severity. An assistant-authored checklist cannot substitute for independent sign-off.
4. **P0 — Public/no-auth scope decision:** The owner **has not approved** a Cloud Run public/no-auth window. Keep the retained Cloud Run service IAM-private. Choose either (A) a separately approved, narrowly time-/cost-bounded public probe with independent network evidence, authorized rollback and review **or** (B) formally remove/revise the separate no-auth acceptance criterion with technical rationale and independent sign-off. Since the already successful normal public-DNS/CA Client run targets IAM-private Cloud Run, a no-auth exposure is not automatically required for protocol correctness, but the written acceptance gate must not be silently waived.
5. **P1 — Operational safety/host compatibility:** Clarify native Go SDK ListTasks access policy, plus supported credential reload, host-side logging/IdP/queue/APM controls, outbound worker hard-crash and unknown-side-effect reconciliation. Cross-host exactly-once is not a Client promise. Host open-public deployment remains under #11.
