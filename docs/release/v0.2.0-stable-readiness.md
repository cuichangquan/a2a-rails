### A1 — completed installed-artifact verification (Step 26-1)

**Evidence:** [PR #64](https://github.com/cuichangquan/a2a-rails/pull/64) / [published-rc2 PostgreSQL run](https://github.com/cuichangquan/a2a-rails/actions/runs/37714046256), Rails 8.0/8.1 PASS with explicit **host-only inflection/migration workarounds**; these are required for the *immutable published rc2*. Then [PR #66](https://github.com/cuichangquan/a2a-rails/pull/66) fixes the underlying Gem naming issue, with clean generated-host production Rails 8.0/8.1 × host inflection 4/4 PASS using a **new source-built installed artifact**. The old published rc2 cannot be fixed retroactively.


Add an isolated reproducible CI/harness using the **published** `a2a-rails = 0.2.0.rc2` Gem, not a `path:` or `git:` source dependency. Pin the known SHA256 and fail on mismatches.

1. Boot clean Rails **8.0 and 8.1** hosts with **PostgreSQL 16** and install the published Gem.
2. Run `bin/rails generate a2a:rails:task_store` and `bin/rails db:migrate`; explicitly set `config.task_store = :active_record`. Verify actual schema/indexes and clean application boot.
3. Configure test-only Bearer authentication matching the Agent Card. Verify public Card and authenticated HTTP Send/Get/List/Cancel Task behavior plus negative cross-tenant Get/List/Cancel/cursor cases.
4. Stop/restart Rails and test from another Rails process against the **same DB**; verify Task survival, owner isolation and concurrent terminal-state consistency.
5. Exercise Task terminal retention, `bin/rails a2a:rails:tasks:stats`, and `bin/rails a2a:rails:tasks:prune` with expired fixture rows; verify bounded deletion and non-expired preservation.
6. Record the **downloaded artifact hash**, complete lockfile versions, PostgreSQL version, exact commands, CI run URLs, successful assertions and deviations. Fail the gate if any step relies on source-tree loading or only in-process SQLite tests.

Passing A1 establishes a **narrow installed-artifact durability proof**, not production database backup, disaster recovery or ingress approval.

### A2 — authentication and tenant isolation

**Step 26-2 verification (2026-10-08): PASS.** [PR #67](https://github.com/cuichangquan/a2a-rails/pull/67) adds [installed-Gem test evidence](../testing/step-26-2-auth-isolation.md) for Rails 8.0/8.1 with a signed local JWT-HS256 **test-only** verifier, negative issuer/audience/expiry/signature/revocation checks, principal/Task/cursor isolation, configuration fail-closed and error/log sanitization. The fixture intentionally does **not** provide a production issuer/verifier or certify a deployed host.


Use a local deterministic issuer/verifier fixture or test-owned token service through the Gem's host `authenticate_request` hook. Confirm: absent/invalid signature, expired, not-yet-valid, wrong issuer/audience, revoked token, wrong tenant, same Task ID attempted across identities, changed pagination filters, missing verifier in production, Agent Card/Bearer consistency, sanitized errors/logs. Real deployment issuer/key-rotation/revocation policies remain B1.

Do **not** add provider-specific OAuth/OIDC servers, Devise, Doorkeeper, or ActingFor hard dependencies to satisfy this gate.

### A3 — durable async semantics

**Step 26-3 verification (2026-10-08): PASS.** [PR #68](https://github.com/cuichangquan/a2a-rails/pull/68) and [queue CI #37718397716](https://github.com/cuichangquan/a2a-rails/actions/runs/37718397716) verify Rails 8.0/8.1 × real Solid Queue and Sidekiq worker processes (4/4 PASS), persistent SQLite ActiveRecordStore, worker SIGKILL during WORKING, restart, duplicate delivery suppression, cancel-before-start, injected synchronous enqueue failure, commit-before-enqueue gap, and a host-owned idempotent business insert under a UNIQUE index. [Failure contracts and reconciliation runbook](../testing/step-26-3-durable-async.md).

This test is not PostgreSQL + real queue under the **same** test process: PostgreSQL row locking and installed candidate compatibility have independent CI evidence. Nothing here guarantees automatic ambiguous WORKING reclamation, exactly-once remote effects, universal retries, or deployment approval. Real host disaster recovery is still gate B3 / Issue #11.


Use actual `ActiveRecordStore` and durable ActiveJob queue. Assert existing queue tests on the release candidate; document/reproduce limits for job re-delivery, cancellation before execution, process restart, failed enqueue after Task commit, ambiguous `WORKING` Tasks and Handler side effects. No generic automatic retries or exactly-once side-effect claims. Host reconciliation and idempotency procedures belong to B3.

### A4 — stable release decision

Only after A1–A3 are reviewed: select a stable source revision, update compatibility/upgrade docs and changelog, set version `0.2.0`, run exact-commit CI/interop/pinned TCK, build **one new stable artifact**, inspect/package/install it, perform security and DB-backed smoke, and record its **new** SHA256. Do not reuse rc2's SHA for a newly built stable Gem. Obtain **separate explicit user approval** for Git tag, GitHub Release, and RubyGems push.
