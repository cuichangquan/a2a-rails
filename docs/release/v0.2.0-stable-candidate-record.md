## Upgrade impact

**Behavioral change from released 0.1.0:** production authentication now fails closed; host must configure verified identities and matching Bearer Agent Card metadata. Task access becomes principal-scoped. Unsupported malformed and oversized input is rejected earlier. Source-built stable candidate fixes Zeitwerk's `a2a` acronym and generated migration naming (#65); the published rc2 cannot be patched. Hosts with already applied migrations must **not** blindly regenerate/rename previously applied migrations.

**Compatibility decisions:** keep default MemoryStore and synchronous execution; ActiveRecordStore and async are explicitly opt-in. No general automatic retries or exactly-once external side effects. An ambiguous WORKING Task after worker crash is not automatically reclaimed. Host must verify permissions within Handlers, select an actual trustworthy credential issuer, operate TLS/ingress/rate/concurrency/cost limits, backup DB and queue, prune Tasks and reconcile uncertain work.

## Decision boundaries (do not conflate)

- **Stable package quality GO/NO-GO:** to be recorded only after the exact `0.2.0` artifact's full CI and SHA256 match.
- **Git tag `v0.2.0`, GitHub Release, RubyGems publication:** **NOT AUTHORIZED in Step 26-4**; a separate, explicit user decision is required for each requested publishing action.
- **Public production deployment:** **NO-GO by default**. Even a passing stable package candidate is not an approval for an unknown Rails host. Host-specific gates B1–B4 remain open in [#11](https://github.com/cuichangquan/a2a-rails/issues/11).
