## Independent public-download verification

After a successful RubyGems push, the first immediate `gem fetch` failed to find the version. Its cause was not established. Recovery used a new temporary directory and the official registry: ordinary `gem fetch a2a-rails -v 0.2.0 --clear-sources --source https://rubygems.org` succeeded. No second push or tag creation was performed.

The downloaded Gem and official RubyGems API metadata both matched the SHA256 above. That public download was installed into a new isolated `GEM_HOME`/`GEM_PATH` using Ruby **3.4.1** and Rails **8.1.4**:

- `require "rails"` and `require "a2a-rails"`: PASS.
- `A2A::Rails::VERSION == "0.2.0"`; installed Gem path inside the isolated host, no checkout code loaded: PASS.
- All 43 installed file contents match the public Gem: PASS.
- Existing production HTTP security smoke, executed against the installed public Gem: PASS.

The post-publication check did not rerun PostgreSQL or the full TCK. Earlier exact-artifact CI and its limitations remain in the [candidate evidence](v0.2.0-stable-candidate-record.md). Official pinned TCK remains **63 passed / 1 failed / 171 skipped / 30 deselected**, with the known `CORE-SEND-003` fixture mismatch; this is not full TCK certification.

## Documentation and deployment boundaries

This record and the updated README, changelog and upgrade guide are post-publication documentation. They do not change the published Gem or the immutable `v0.2.0` tag; the tagged documentation retains the earlier candidate wording.

Default Task storage remains process-local MemoryStore and execution remains synchronous. Public production deployment still requires host-specific controls and review under [Issue #11](https://github.com/cuichangquan/a2a-rails/issues/11), which remains open. Stable Gem publication does not approve a deployed endpoint.
