- [Stable exact-candidate CI](../../.github/workflows/v0.3-client-private-candidate.yml) checks out the **PR HEAD source SHA** (not GitHub's synthetic merge SHA), makes a clean `git archive` from that commit, executes **one** `gem build` and uploads a single `a2a-rails-0.3.0.gem` with `SOURCE_COMMIT`, `SHA256SUMS`, `STAGING_DELTA=NONE`.
- RubyGems package metadata (name `a2a-rails`, version `0.3.0`, Ruby min), required runtime files, and the SHA256 of **every** packaged file (including README/CHANGELOG) must match the actual frozen checkout. No foreign/unexpected packaged files are accepted.
- Each dependent CI job downloads **the same upstream build-once Gem artifact**, checks `sha256sum -c SHA256SUMS`, verifies the frozen `SOURCE_COMMIT` matches HEAD and then installs the local Gem. No dependency job rebuilds the candidate, installs an unpublished public version, or loads Client code from the workspace.
- The CI Gem archive (with hash/SHA metadata) is retained only temporarily (**30 days**). Download the **actual successful run artifact** for further review. Do not recalculate its hash from a second build and call it the original.
- Separate [installed package security/PG matrix](../../.github/workflows/release-candidate-artifact.yml) gives a redundant check but produces **its own** distinct candidate Gem; it is **not** substituted for the build-once artifact above.

## Security advisory findings discovered during candidate verification (NOT hidden)

The first actual 0.3.0 candidate [PR-head audit run #38053639030](https://github.com/cuichangquan/a2a-rails/actions/runs/38053639030) **FAILED in all 6 resolved Rails host graphs**, even though build-once/Client/PG/Python-Go/Echo jobs succeeded. Current RubySec DB at scan time reported:

| Dependency / exact version observed | Advisory and severity in RubySec | Resolution / who owns it |
| --- | --- | --- |
| `json 2.9.1` / `2.18.0` | [GHSA-x2f5-4prf-w687](https://github.com/ruby/json/security/advisories/GHSA-x2f5-4prf-w687) (Low) and, for `2.18.0`, [GHSA-3m6g-2423-7cp3](https://github.com/ruby/json/security/advisories/GHSA-3m6g-2423-7cp3) (RubySec criticality Unknown) | **Direct Gem dependency** tightened in this candidate to `json >=2.19.9,<3` to exclude the documented affected versions. Re-test all Ruby 3.3/3.4/4.0 hosts before accepting. |
| `net-imap 0.4.25` | [GHSA-8p34-64r3-mwg8](https://github.com/ruby/net-imap/security/advisories/GHSA-8p34-64r3-mwg8) (Medium), [GHSA-c4fp-cxrr-mj66](https://github.com/ruby/net-imap/security/advisories/GHSA-c4fp-cxrr-mj66) (Low), [GHSA-46q3-7gv7-qmgg](https://github.com/ruby/net-imap/security/advisories/GHSA-46q3-7gv7-qmgg) (Medium) | **Indirect dependency of the complete Rails host/mail feature**, not `a2a-rails` runtime. The candidate's independent audit host explicitly requests patched `net-imap ~>0.5.15`. **Real applications must update their own Gemfile.lock; Gem distribution cannot enforce the whole host's mail dependency set.** |

This is a **real finding in specific resolved dependency graphs**, not a test fixture that should be ignored. The initial failed CI runs remain visible. The updated Gem's tighter `json` bound is a deliberate runtime dependency **compatibility change** compared with RC1; re-run supported-host and published-RC1 comparison gates. An audited demo host choosing safe `net-imap` does **not** prove unrelated applications with older `net-imap` are safe, and no host-specific mitigations are represented as global vulnerability elimination.

**Current result:** patched-version PR-head audit is **pending fresh green checks**; do not overwrite this finding or mark stable release GO while any advisory job is failing. The final distinct source SHA, package SHA256 and actual Gemfile.lock snapshots will be recorded in Step 31-6 only after final tests.

## Test boundaries

- All test-only origin/IP override and temporary TLS trust anchors stay **inside CI fixtures**. Production Client still rejects loopback/private/metadata IPs and verifies HTTPS DNS, certificates and SNI.
- The Echo Server uses published `a2a-rails 0.2.0`, pinned independent repo SHA. Its local HTTP Card advertises an HTTP RPC URL; the CI bridge rewrites **only its advertised interface URL**, not its Echo implementation.
- No public-CA/public-DNS no-injection end-to-end proof is asserted from the local TLS bridge alone; earlier controlled IAM-private test evidence belongs to a different scope.
- No external identity-provider security assessment, general adversarial audit, host APM/filter guarantee or production deployment signoff is implied.
- RubySec is a dated snapshot of resolved Ruby dependencies; future advisories and application-specific dependencies remain outside this package scan.
- No unapproved public Cloud Run/IAM/ingress changes, billable infrastructure, secrets, or data fixtures.
