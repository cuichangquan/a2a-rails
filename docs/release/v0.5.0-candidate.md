## Maintainer summary

A Handler can ask a question and later complete the same Task with an additional
answer. Task identity is stable while each execution has a distinct turn UUID;
this prevents an old Job or delayed error handler from writing a newer answer's
result. It does **not** guarantee external business effects happen exactly once,
identify the intended question of every delayed new-ID answer, or safely retry
an ambiguous WORKING Task.

## Behavior corrections and limits

SendMessage now honors standard `configuration.historyLength` (previously ignored
because handler looked at top-level while SDK schema discarded it). Get/List keep
top-level historyLength. No saved input is removed when response history is zero.

Async retains the existing immediately-returning profile; explicitly request
`configuration.returnImmediately: true`. False/unset blocking behavior of the full
standard remains unsupported. No SSE, auth-required, general workflow engine,
SDK switching, new cloud resources or broad refactoring.
