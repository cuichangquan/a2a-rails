# a2a-rails v0.1.0 Release Notes

## Summary

`a2a-rails` v0.1.0 is the first release of a Rails-native integration Gem for exposing Rails applications as A2A v1.0 agents.

The Gem keeps the A2A SDK behind an internal protocol boundary so Rails applications can define Agents, Skills, Handlers, routing, and configuration with ordinary Ruby APIs.

## Highlights

- Rails applications can expose an A2A Agent Card at `/.well-known/agent-card.json`.
- A2A JSON-RPC requests are accepted at `/a2a`.
- Applications define Agents and Skills with `A2A::Rails::Agent`.
- Handlers receive SDK-independent Ruby Hashes.
- One Skill dispatches automatically; multiple Skills use an application-owned Router.
- Synchronous Task execution supports `SendMessage`, `GetTask`, `ListTasks`, and `CancelTask`.
- The default Task Store is thread-safe and process-local.
- `install` and `agent` generators provide a minimal Rails setup.
- No explicit Engine mount, ActiveRecord table, or ActiveJob setup is required.

## Quick Start

```bash
bundle add a2a-rails
bin/rails generate a2a:rails:install
bin/rails generate a2a:rails:agent echo
```

A minimal Agent:

```ruby
class EchoAgent < A2A::Rails::Agent
  name "Echo Agent"
  description "Echo messages"
  version "1.0"

  skill :reply,
    description: "Echo a message",
    tags: %w[echo],
    handler: Echo::Reply
end
```

Register it:

```ruby
A2A::Rails.configure do |config|
  config.agent = "EchoAgent"
  config.public_base_url = ENV["A2A_PUBLIC_BASE_URL"]
end
```

See `README.md` for the complete Echo Quick Start.

## Scope and Limitations

v0.1.0 is intentionally server-first and non-streaming.

Not included:

- A2A Client
- ActiveRecord Task Store
- ActiveJob Task execution
- SSE / BiDi Streaming
- Push Notifications
- gRPC
- Human-in-the-loop flows
- `INPUT_REQUIRED` / `AUTH_REQUIRED`
- OAuth Server
- Agent Registry / Marketplace
- ActingFor integration
- Admin UI
- LLM or orchestration framework

The default Task Store is process-local and not durable. Cancellation changes Task state atomically but does not stop already-running Handler code or reverse application side effects.

## Security / Logging Note

The upstream SDK can emit an INFO log containing the Rack environment. The Rails-facing integration suppresses that upstream Triage log at the boundary and restores the prior logger state afterward.
