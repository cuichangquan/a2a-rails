## Supported scope and limits

A Handler can return the SDK-independent `InputRequired` result, then accept an
answer through SendMessage on the same Task. The release includes atomic reply
acceptance, per-turn execution fencing, bounded messageId deduplication, an
additive durable-store migration and request-local Rails parameter log filtering.
See [continuation usage](../guides/task-continuation.md) and the
[0.4.0 upgrade/recovery guide](upgrading-v0.4.0-to-v0.5.md), especially custom
Stores, old-worker rollout and ambiguous execution recovery.

The informational pinned TCK remains partial: **63 passed / 1 known failure /
171 skipped / 30 deselected** ([upstream CORE-SEND-003](https://github.com/a2aproject/a2a-tck/issues/202)).
A successful informational workflow is not full A2A conformance. The existing
async immediately-returning profile, lack of SSE/push/gRPC and continuation
recovery limits are unchanged. Neither exactly-once external business effects
nor safe automatic retry of ambiguous WORKING Tasks is promised.
