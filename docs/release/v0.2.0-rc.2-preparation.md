# v0.2.0-rc.2 release-candidate preparation decision

> **Candidate preparation only.** This document authorizes verification of `0.2.0.rc2`. It does **not** authorize a Git tag, GitHub Release, RubyGems publication, or a claim of open-public-production readiness.

Date: 2026-10-07  
Baseline published release: `a2a-rails 0.1.0`  
Candidate version: **`0.2.0.rc2`**  
User-facing candidate name: **`v0.2.0-rc.2`**  
Tracking: [Issue #54](https://github.com/cuichangquan/a2a-rails/issues/54)

## Why a new candidate

The Step 20 `0.2.0.rc1` candidate predates two material runtime additions:

- Step 21: optional durable ActiveRecord Task Store + lifecycle maintenance;
- Step 22: optional ActiveJob Task execution + async lifecycle semantics.

Therefore rc1's commit, artifact and SHA256 remain valid only for that historical tree and cannot be reused as release evidence for current main.

## Candidate scope

The candidate includes the post-v0.1 security hardening, direct Message / File Artifact work, ActiveRecord Task Store, and ActiveJob Task execution currently merged on main.

Important defaults and boundaries remain:

- synchronous Task execution remains the default;
- direct Message responses remain synchronous;
- MemoryStore remains the default Store;
- production async requires both a shared/durable Task Store and a durable ActiveJob backend;
- no generic Handler retry or generic exactly-once external-side-effect guarantee;
- cancellation of running Handler code is logical/best-effort;
- ambiguous WORKING Tasks are not blindly replayed;
- host applications remain responsible for real credential verification and business authorization.

## Verification gates

Before this candidate can be considered reviewable:

1. Ruby 3.3/3.4/4.0 + Rails 8.0/8.1 regression matrix passes on the exact candidate tree.
2. PostgreSQL Task Store persistence / locking / claim coverage passes.
3. Solid Queue + Sidekiq separate-worker and real HTTP async E2E passes on Rails 8.0/8.1.
4. Production-shaped security smoke passes.
5. Official Python SDK 1.2.2 + Go SDK v2.6.0 interoperability passes.
6. Pinned official A2A TCK is rerun and the known CORE-SEND-003 upstream fixture issue is distinguished from Gem regressions.
7. One exact `.gem` is built, inspected, installed into clean Rails 8.0 and 8.1 hosts, and its SHA256 is recorded.
8. Final candidate record identifies the exact commit and all evidence.

## Publication gate

Even if every verification gate passes:

- **do not create a tag;**
- **do not create a GitHub Release;**
- **do not publish to RubyGems**

without a new explicit user approval.

Issue #11 remains the deployment-specific production-security gate and is not closed by candidate verification.
