**TCK reporting nuance:** The official pinned TCK suite had **63 tests passed / 1 known upstream-fixture-related `CORE-SEND-003` failed / 171 skipped / 30 deselected**. The TCK *workflow* is informational and its success does **not** certify full A2A conformance; [upstream a2a-tck#202](https://github.com/a2aproject/a2a-tck/issues/202) remains an independent known issue.

**Security provenance:** An early candidate dependency audit found affected older `json` and Rails-host `net-imap` versions. The published Gem tightened its **direct** `json` dependency to `>=2.19.9,<3`; the independently audited **host application** lockfiles used `net-imap ~>0.5.15` as the Rails mail dependency. Each of the six resolved final candidate RubySec audits passed at their scan time. This is **not** a guarantee that arbitrary consumer `Gemfile.lock` files have no advisories, or an external security certification. Initial failing runs were preserved as historic evidence.

## Scope, residual risks and maintenance

- **Published library:** A2A v1.0 JSON-RPC Server integration and outbound `A2A::Rails::Client`, Client-only mode, and documented input/transport/credential bounds.
- **Outside current support:** SSE/streaming, push, gRPC, IPv6-only outbound Agent sockets, generic auto-poll/retry or remote exactly-once effects. Consumers remain responsible for IdP issuer verification, tenant/business authorization, secrets/log/APM controls, outbound network controls, durable Store/queue operations and dependency maintenance.
- **Independent external security audit [#113](https://github.com/cuichangquan/a2a-rails/issues/113):** recommended, explicitly optional, not a known vulnerability. **Unknown RC1 user adoption** was accepted as a managed risk for Gem distribution; lack of external reports is not proof of no defects.
- **Public/no-auth production deployment [#11](https://github.com/cuichangquan/a2a-rails/issues/11): still NO-GO** without deployment-specific authentication, policy, observability and operational checks. The Gem release does not change that.
- Historical release and candidate README/CHANGELOG text captured at the immutable `v0.3.0` tag may describe planning and verification. **Post-publication documentation changes to main are new commits** and do not modify the tagged original Gem or its SHA256. README and CHANGELOG are included in the Gem package; any later local rebuild from documentation-updated main can differ and **must not** be described as byte-identical with this immutable published `0.3.0` Gem.

## Consumer use

```bash
gem install a2a-rails -v 0.3.0
```

Use `gem "a2a-rails", "= 0.3.0"` in a Rails Gemfile and verify the application's resolved `Gemfile.lock` and authorization/security configuration before production.
