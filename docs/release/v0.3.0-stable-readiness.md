## 4. Known remaining decisions / gaps

1. **Final release-scoped security assessment not performed for the stable candidate.** Inspect the complete `v0.2.0` → candidate source delta, bounded URL/DNS/transport, TLS/credential origin isolation, error/log privacy, protocol DTOs, timeout effects, tenant ownership and store/queue assumptions. Check credible public/private reports and dependency advisories where accessible; fix known Critical/High findings before GO.
2. **Feedback window is very short:** RC1 was published on 2026-10-10. No verified broad adopter feedback is established by this assessment. Lack of feedback is uncertainty, **not proof of safety**; record and decide an acceptable stable-release window.
3. **API/compatibility freeze needed:** document Ruby >= 3.3, Rails >= 8.0 and < 8.2, A2A v1.0, JSON-RPC; Client IPv4-only (IPv6-only unsupported), no SSE/push/gRPC, no orchestration/automatic retry, Task vs direct Message shapes. Verify the stable version and README/CHANGELOG/upgrade docs are consistent.
4. **Stale snapshot wording:** several historical `ROADMAP.md`, release policy, issue and security checklist sections still say RC1 is unapproved/unpublished or PR #112 is open. Retain historical provenance but give stable-release readers a **clear latest-status pointer**, rather than silently rewriting historical decision records.
5. **Stable exact candidate not built:** `lib/a2a/rails/version.rb` remains `0.3.0.rc1`. A future `0.3.0` must update release notes/version-pinned workflows, freeze final SHA, build **once** and verify the exact `0.3.0` bytes after installation with the appropriate CI matrix. Distinguish review-build artifact from eventual published artifact.
6. **No publication approval:** tagging, GitHub Release creation, RubyGems push and new cloud deployment still require separate owner authorization. The current Step 31-1 documentation activity is not that approval.
