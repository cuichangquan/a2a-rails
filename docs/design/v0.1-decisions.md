# a2a-rails v0.1 Design Decisions

## 1. Project Goal

a2a-rails は、

> Railsアプリを、RailsらしくA2A Agentとして公開するためのRails Integration Gem

を目指す。

English:

> Expose Rails applications as A2A agents using Rails-native conventions.

---

## 2. Positioning

a2a-rails は A2A Protocol SDK ではない。

```text
A2A Protocol
     ↓
Ruby A2A SDK
     ↓
a2a-rails
     ↓
Rails Application
     ↓
Business Logic
```

a2a-rails 自身では Protocol を再実装しない。

---

## 3. Ruby A2A SDK

現時点では、下層SDKの第一候補として `agent2agent` を検討する。

理由:

- A2A Server 対応
- A2A Client 対応
- JSON-RPC 対応
- HTTP+JSON 対応
- Rack / Rails から利用可能
- Task lifecycle を扱える
- Streaming にも対応可能

`simple_a2a` も候補だが、v0.1では `agent2agent` を優先して検討する。

ただし、a2a-rails の Public API を `agent2agent` 固有APIへ依存させない。

---

## 4. SDK Boundary

構造は以下を基本とする。

```text
Rails Application
      ↓
A2A::Rails::Agent
Skill
Handler
      ↓
Dispatcher
      ↓
Internal Protocol Boundary
      ↓
Agent2Agent Adapter
      ↓
agent2agent
      ↓
A2A Protocol
```

Adapter は v0.1 から内部的には存在してもよいが、Public API として公開しない。

例えば以下のような設定は、v0.1ではまだ提供しない。

```ruby
config.protocol_adapter = :agent2agent
```

将来、Official Ruby SDK などが登場した場合に交換可能な構造だけ確保する。

---

## 5. Public API Policy

Rails開発者にはProtocol固有コードをできるだけ見せない。

v0.1 の基本API:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

Handler:

```ruby
class Shopping::SearchProducts
  def self.call(message:, context:)
    # Rails business logic
  end
end
```

Public APIへ以下を漏らさない。

```text
Rack env
A2A Protocol Schema
JSON-RPC implementation
Transport implementation
SDK固有Error
SDK固有Request object
```

---

## 6. Terminology

A2A標準用語を可能な限りそのまま使う。

### Agent

A2Aとして外部公開されるAgent。

a2a-railsでは:

```ruby
A2A::Rails::Agent
```

### Agent Card

Agentの情報・Skill・接続方法などを公開するA2A標準情報。

Rails側のAgent定義から生成する。

### Skill

Agentが外部に提供する能力。

例:

```ruby
skill :search_products
```

### Message

Agent間でやり取りするA2A Message。

独自Message classは原則作らない。

### Task

A2A標準のTask。

独自Task lifecycleを作らず、A2A標準の状態を使用する。

### Artifact

Taskによって生成された成果物。

### Handler

a2a-rails側の概念。

A2A SkillとRails Business Logicを接続する。

```text
A2A Skill
    ↓
Handler
    ↓
Rails Service
```

---

## 7. Core Architecture

```text
Remote A2A Client
       │
       ▼
Ruby A2A SDK
       │
       ▼
Protocol Adapter
       │
       ▼
Dispatcher
       │
       ▼
Skill
       │
       ▼
Handler
       │
       ▼
Rails Business Logic
```

a2a-rails の中心的責務は、

> A2A SkillをRails Business Logicへdispatchすること

とする。

## 8. v0.1 Scope

### Included

- Rails integration
- `A2A::Rails::Agent`
- Skill DSL
- Handler dispatch
- Agent Card generation
- `/.well-known/agent-card.json`
- A2A request受付
- 最小限のTask lifecycle
- Rails Engine / Routes
- Configuration
- Generator
- Rails Logging
- Test support

### Not Included

- A2A Client
- 独自A2A Protocol
- 独自Transport
- gRPC
- Push Notification
- BiDi Streaming
- Human-in-the-loop
- Agent Registry service
- Agent Marketplace
- OAuth Server
- Authorization Engine
- ActingFor integration
- Admin UI
- LLM Agent Framework
- Orchestration Framework

---

## 9. Server First

v0.1はServer Sideに集中する。

```text
Remote A2A Agent
       ↓
a2a-rails
       ↓
Rails Application
```

Client機能はv0.1では対象外。

最初の成功条件は、

```text
1. GemをRailsへ追加
2. Agent / Skillを書く
3. 他のA2A Agentから呼び出せる
```

とする。

---

## 10. Streaming

v0.1ではNon-Streaming Serverを優先する。

```text
v0.1

✅ 基本Request / Response
✅ Message処理
✅ Task処理

❌ SSE Streaming
❌ Subscribe
❌ BiDi Streaming
```

理由:

- 既存Railsアプリへの導入を簡単にする
- Web Server構成への依存を増やさない
- v0.1のScopeを小さく保つ

Streamingは後続バージョンで検討する。

---

## 11. Task Persistence

Task persistenceはRails Integration側で扱えるようにする。

ただし、ActiveRecord / ActiveJobをv0.1の必須要件にはしない。

将来的には:

```text
A2A Task
   ↓
a2a-rails Task Store
   ↓
ActiveRecord

A2A Task
   ↓
ActiveJob
   ↓
Rails Service
```

のようなIntegrationを検討する。

---

## 12. ActingFor

a2a-railsとActingForは別Gemとして維持する。

```text
a2a-rails
    ↓
Agent Communication

ActingFor
    ↓
Delegated Authorization
```

a2a-rails本体からActingForへ依存しない。

将来的に必要であればIntegration Gemを検討する。

例:

```text
acting_for-a2a
```

---

## 13. Design Principles

新機能を追加するときは以下を確認する。

1. v0.1に本当に必要か
2. Ruby A2A SDK側の責務ではないか
3. Rails Integration Layerの責務か
4. RailsらしいAPIか
5. A2A標準と衝突しないか
6. SDK固有実装がPublic APIへ漏れていないか
7. 将来SDKを交換できるか
8. 過剰設計になっていないか

最重要ルール:

> Protocolを再発明しない。

> Rails Integrationに集中する。

---

## 14. Current Architecture Decision

現時点の基本方針:

```text
A2A Standard
     ↓
Ruby A2A SDK
     ↓
Thin Protocol Boundary
     ↓
a2a-rails Dispatcher
     ↓
Rails Handler
     ↓
Rails Business Logic
```

v0.1では `agent2agent` をRuby A2A SDKの第一候補として検討する。

ただし、Public APIからSDK固有実装を隠し、将来のSDK変更に備える。

## 15. Public API Design

### Agent DSL

Railsアプリ側は `A2A::Rails::Agent` を継承して公開Agentを定義する。

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

`ShoppingAgent` は用途例であり、Gemは特定ドメイン専用ではない。

### Skill DSL

SkillはSymbolで宣言する。

```ruby
skill :search_products,
  description: "Search products",
  tags: %w[shopping search],
  handler: Shopping::SearchProducts
```

基本方針:

- Skill ID はSymbolから生成する
- Skill name はIDから自動生成し、必要なら明示的に上書き可能にする
- `description` は必須
- `tags` は必須
- `handler` は必須
- `examples` などのA2A標準オプション情報は必要に応じて指定可能にする
- Protocol固有の定型情報は可能な限りGem側で補完する

### Handler Interface

標準Handler Interface:

```ruby
class Shopping::SearchProducts
  def self.call(message:, context:)
    # Rails business logic
  end
end
```

方針:

- SDK固有Request objectをHandlerへ渡さない
- Rack envをHandlerへ渡さない
- `message` と `context` をRails側の安定した境界として扱う
- HandlerはRails Service / Modelなど既存Business Logicを呼び出す
- Handlerの戻り値からA2AのMessage / Task / Artifactへの変換はGem内部で扱う

### Agent Registration

v0.1では **1 Rails Application = 1 Public A2A Agent** とする。

公開Agentはinitializerで明示登録する。

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
end
```

方針:

- Agentクラスを作っただけでは外部公開しない
- 登録したAgentのみ公開する
- reload / autoloadを考慮し、Agentはクラス名文字列で登録できるようにする
- 複数Agent公開はv0.1の対象外とし、必要なら後続バージョンで検討する

推奨配置:

```text
app/
└── agents/
    └── shopping_agent.rb
```

### Routing

v0.1では標準RouteをGem側で提供する。

```text
GET  /.well-known/agent-card.json
POST /a2a
```

方針:

- 利用者が通常 `routes.rb` にmountを書く必要はない
- v0.1では標準Routeを固定する
- Agent Card endpointとA2A request endpointをGem内部のRails Engine / Routesで提供する

### Configuration API

v0.1のConfiguration APIは小さく保つ。

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
  config.public_base_url = ENV["A2A_PUBLIC_BASE_URL"]
  config.logger = Rails.logger
end
```

設定:

- `agent`: 必須。公開するAgentクラス名
- `public_base_url`: 任意。外部公開URLを自動判定できない場合に指定
- `logger`: 任意。デフォルトは `Rails.logger`

v0.1では以下をPublic Configurationに出さない。

```ruby
config.protocol_adapter = :agent2agent
config.transport = :json_rpc
config.streaming = false
config.sdk_options = {}
```

Protocol / SDK / Transport固有設定は内部実装として隠す。

### Error Handling API

Protocol固有ErrorをRails開発者へ直接扱わせない。

基本分類:

```text
Invalid A2A Request
        ↓
SDK / Protocol Adapter
        ↓
A2A standard error

Unexpected Handler Exception
        ↓
a2a-rails
        ↓
Rails logger
        ↓
FAILED Task

Business Logic Rejection
        ↓
Task lifecycle
        ↓
REJECTED Task
```

Gem自身の設定・実装エラーには共通基底Errorを持つ。

```text
A2A::Rails::Error
A2A::Rails::ConfigurationError
A2A::Rails::UnknownSkillError
A2A::Rails::InvalidHandlerError
```

A2A ProtocolのJSON-RPC errorやSDK固有ErrorはPublic APIへ露出させない。

## 16. Agent Card Design

v0.1では、Rails側のAgent / Skill DSLからA2A Agent Cardを自動生成する。

設計原則:

> Rails開発者はAgentの意味的な情報を書く。

> Protocol固有の定型情報はGem側で補完する。

### Agent Card Endpoint

```text
GET /.well-known/agent-card.json
```

A2A request endpoint:

```text
POST /a2a
```

### Public Endpoint URL

Agent Cardの `supportedInterfaces[].url` は以下の優先順位で生成する。

```text
1. config.public_base_url
        ↓ 未指定の場合
2. request.base_url
        ↓
3. /a2a を付与
```

例:

```ruby
A2A::Rails.configure do |config|
  config.public_base_url = "https://example.com"
end
```

生成結果:

```text
https://example.com/a2a
```

`public_base_url` には `/a2a` を含めない。

Reverse Proxy / Load Balancerなどにより外部URLをRequestから正しく判定できない場合は、`public_base_url` の明示設定を推奨する。

### Supported Interface

v0.1ではNon-Streaming JSON-RPC Serverとして公開する。

```json
{
  "supportedInterfaces": [
    {
      "url": "https://example.com/a2a",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ]
}
```

Rails開発者には `protocolBinding` / `protocolVersion` を通常設定させない。

### Agent Field Mapping

Rails DSL:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"
end
```

Mapping:

```text
name        → Agent Card name
description → Agent Card description
version     → Agent Card version
```

Agent側では以下を必須とする。

- `name`: 空でないString
- `description`: 空でないString
- `version`: 空でないString
- `skills`: 1件以上

### Skill Mapping

Rails DSL:

```ruby
skill :search_products,
  description: "Search products",
  tags: %w[shopping search],
  examples: ["Search for a laptop under $1000"],
  handler: Shopping::SearchProducts
```

Mapping:

```text
skill Symbol  → skills[].id
name          → skills[].name
description   → skills[].description
tags          → skills[].tags
examples      → skills[].examples
input_modes   → skills[].inputModes
output_modes  → skills[].outputModes
handler       → Agent Cardには出力しない
```

Skill `name` を省略した場合、IDから自動生成する。

```text
search_products
      ↓
Search Products
```

必要なら明示的に上書き可能とする。

```ruby
skill :search_products,
  name: "Product Search",
  description: "Search products",
  tags: %w[shopping search],
  handler: Shopping::SearchProducts
```

Skill側のValidation:

- IDはSymbolで宣言する
- IDはAgent内で重複不可
- `description` は必須・空文字不可
- `tags` は必須・1件以上
- `handler` は必須
- Handlerは `.call` に応答すること
- `examples` は任意の `Array<String>`
- `input_modes` は任意の `Array<String>`
- `output_modes` は任意の `Array<String>`

### Default Input / Output Modes

v0.1のAgent全体のデフォルト:

```json
{
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"]
}
```

Agent DSLではv0.1時点でこの設定を公開しない。

特殊なSkillのみ必要に応じて上書き可能とする。

```ruby
skill :analyze_image,
  description: "Analyze an image",
  tags: %w[image analysis],
  input_modes: ["image/png", "image/jpeg"],
  output_modes: ["text/plain"],
  handler: Image::Analyze
```

### Capabilities

v0.1では以下をサポートしない。

```text
streaming          → unsupported
pushNotifications  → unsupported
extendedAgentCard  → unsupported
extensions         → none
```

概念上のAgent Card:

```json
{
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false
  }
}
```

SDKのserializationにより `false` field自体が省略されてもよい。

Public APIとしてはJSON上の `false` の存在ではなく、該当機能がunsupportedであることを保証する。

Rails開発者には以下のような設定を提供しない。

```ruby
config.streaming = false
config.push_notifications = false
config.extended_agent_card = false
```

実装されていないCapabilityを設定だけで有効化できないようにする。

### Optional Agent Card Fields

v0.1では以下を公開しない。

```text
provider
iconUrl
documentationUrl
securitySchemes
securityRequirements
signatures
extensions
```

理由:

- 最小Server実装に必須ではない
- Security / Authenticationは別設計として扱う
- Agent Card署名はv0.1 Scopeを超える
- 表示用metadataは後から互換性を保って追加しやすい

### Validation Timing

Step 14でValidationのタイミングを具体化した。

- Gem追加・initializer生成だけでは、Agent未登録・未完成を理由にRails起動を失敗させない。
- `config.agent` のresolveとAgent / Skill / Handler / Routerの検証は、A2A endpoint利用時に行う。
- Railsのautoload / reloadを考慮し、initializer内でAgentクラスを強制resolveしない。
- Agent Card生成・Handler dispatch前に定義全体を検証する。
- アプリ独自Rubyコードの構文エラーなどまで抑制する方針ではない。

### Invalid Agent Card

Validationに失敗したAgent Cardは外部公開しない。

```text
GET /.well-known/agent-card.json
        ↓
Validation failure
        ↓
500 Internal Server Error
        +
Rails logger
```

内部のRuby class名・stack trace・SDK固有Errorなどを外部レスポンスへ漏らさない。

Gem側の設定・定義エラーには既存Error hierarchyを利用する。

```text
A2A::Rails::Error
├── A2A::Rails::ConfigurationError
├── A2A::Rails::UnknownSkillError
└── A2A::Rails::InvalidHandlerError
```

Agent / Skill validation専用Error classをv0.1で過剰に増やさない。

### Final v0.1 Agent Card Example

Rails側:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

Configuration:

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
  config.public_base_url = "https://example.com"
end
```

概念上生成されるAgent Card:

```json
{
  "name": "Shopping Agent",
  "description": "Search and purchase products",
  "version": "1.0",
  "supportedInterfaces": [
    {
      "url": "https://example.com/a2a",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ],
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "search_products",
      "name": "Search Products",
      "description": "Search products",
      "tags": ["shopping", "search"]
    }
  ]
}
```

重要:

- `handler` はAgent Cardへ出力しない
- Protocol / Transport固有の定型情報はGem側で補完する
- v0.1ではA2A標準に必要な最小情報だけを公開する
- 特定ドメイン向けのAgent設計にはしない

## 17. Task Lifecycle Design

v0.1では、A2A標準のTaskを使用し、独自Task lifecycleは作らない。

設計原則:

> Rails開発者はBusiness Logicを書く。

> Task生成・状態遷移・Artifact変換・Protocol Error変換はGem内部で扱う。

### Basic Lifecycle

v0.1の基本状態遷移:

```text
SUBMITTED
    ↓
WORKING
    ├──→ COMPLETED
    ├──→ FAILED
    └──→ REJECTED
```

終了状態:

```text
COMPLETED
FAILED
REJECTED
```

終了状態から別状態へ再遷移しない。

A2A標準状態として `CANCELED` も認識するが、v0.1では `CancelTask` を実装しないため、通常の実行フローから `CANCELED` へは遷移しない。

以下はv0.1 Scope外:

```text
INPUT_REQUIRED
AUTH_REQUIRED
```

Human-in-the-loopや追加認証フローは後続バージョンで検討する。

### Task Creation Boundary

v0.1では、実行対象となる有効なMessageを受け付けた場合、Taskを生成してHandlerを同期実行する。

```text
A2A Message
    ↓
Task creation
    ↓
SUBMITTED
    ↓
WORKING
    ↓
Handler
    ↓
Artifact
    ↓
COMPLETED / FAILED / REJECTED
```

v0.1ではTask結果を直接Messageとして返す独自分岐を作らず、Task + Artifactを基本とする。

### Handler Result Mapping

正常return:

```text
Handler return
    ↓
COMPLETED
```

意図的な拒否:

```ruby
raise A2A::Rails::RejectedTask, "Request is not allowed"
```

```text
A2A::Rails::RejectedTask
    ↓
REJECTED
```

想定外Exception:

```text
Unexpected Exception
    ↓
Rails logger
    ↓
FAILED
```

検索結果0件や空配列など、Business Logicとして正常に処理できた結果は `FAILED` にしない。

### Artifact Mapping

Handlerの正常な戻り値はTask Artifactへ自動変換する。

```text
String       → Text Part
Hash / Array → Data Part
nil          → ArtifactなしでCOMPLETED
```

ActiveRecord objectなどをGemが暗黙にserializeしない。

外部公開データはHandler側で `Hash` / `Array` などへ明示変換する。

### Task ID / Context ID

`task_id`:

- 新規TaskごとにServer側で生成する
- Rails Handlerは生成・管理しない
- 実際のID生成を下層SDKへ委譲してもよいが、責務境界はProtocol Boundaryに置く

`context_id`:

- Client提供値があれば維持する
- 未指定ならServer側で生成する
- 複数Taskを同じ会話・処理contextへ関連付けられる

既存Task参照時:

```text
task_idのみ
    → Taskからcontext_idを解決

未知のtask_id
    → TaskNotFoundError

task_id + context_idが不一致
    → request reject
```

### Task Store

Task保存には内部抽象を持つ。

概念上:

```ruby
store.save(task)
store.find(task_id)
store.update(task)
```

v0.1のデフォルトはMemory Task Storeとする。

```text
A2A Task
   ↓
Task Store
   ↓
Memory
```

v0.1では:

- ActiveRecordを必須にしない
- ActiveJobを必須にしない
- ActiveRecord Task StoreはScope外
- Task Store選択用Public Configurationはまだ公開しない
- HandlerからTask Storeを直接操作させない

Memory Task Storeの制約:

- Rails processをまたいだ共有を保証しない
- Rails再起動後のTask保持を保証しない
- 本番向け永続Task Storeは後続バージョンで検討する

### Lifecycle Responsibility

Task lifecycleは内部の専用コンポーネントで管理する。

概念名:

```ruby
A2A::Rails::TaskLifecycle
```

責務:

```text
Dispatcher
    → Skill / Handlerを選択してdispatch

TaskLifecycle
    → Task生成・状態遷移

Handler
    → Rails Business Logic

TaskStore
    → Task保存
```

Task状態をRails開発者が直接変更するPublic APIは提供しない。

### Error Exposure

Unexpected Handler Exception:

```text
外部: FAILED + generic message
内部: Rails loggerへ例外詳細
```

例えば外部には:

```text
Task execution failed
```

程度の一般化されたmessageを返し、stack trace、DB接続先、Rails内部class名などを漏らさない。

`A2A::Rails::RejectedTask` は意図的なBusiness rejectionなので、指定された安全な理由を `REJECTED` のmessageとして返せる。

Protocol ErrorはTask failureと分離する。

```text
Invalid A2A Request
Unknown Task
Unsupported Operation
    ↓
A2A Protocol Error
```

これらを `FAILED` Taskへ変換しない。

### Timestamp / History

`TaskStatus.timestamp` は状態変更時にGem側でUTC時刻を自動設定する。

Rails Handler側ではtimestampを管理しない。

`Task.history` はA2A Message履歴として扱い、状態遷移履歴として使用しない。

v0.1ではTask作成につながった受信Messageを保持できる構造を基本とする。

状態遷移はRails loggerへ記録する。

```text
task_id=... state=submitted
task_id=... state=working
task_id=... state=completed
```

独自status history modelは作らない。

### GetTask

v0.1では `GetTask` をサポートする。

```text
GetTask(task_id)
    ↓
Task Store
    ↓
Taskあり → current Taskを返す
Taskなし → TaskNotFoundError
```

取得対象:

- current status
- artifacts
- message history

A2A標準の `historyLength` に従い、返却するhistory件数を制限できる構造とする。

Taskの永続性はTask Storeの能力に依存するため、Memory Task Storeでは再起動後や別processからの取得を保証しない。

### ListTasks

v0.1では `ListTasks` を実装しない。

理由:

- filtering
- ordering
- cursor pagination
- authorization scope

などが必要になり、最小Server Scopeを超えるため。

呼ばれた場合はA2A標準のUnsupported Operationとして扱う。

Task Storeにもv0.1ではlist / filter / pagination APIを要求しない。

### CancelTask

v0.1では `CancelTask` を実装しない。

```text
CancelTask
    ↓
Unsupported Operation
```

同期Handler実行を安全に停止するためのbackground execution / cancellation signalなどはv0.1 Scope外とする。

`CANCELED` state自体はA2A標準状態として認識し、将来async executionを導入した際に正式対応する。

### Final v0.1 Task Scope

```text
SendMessage / Task execution  ✅
GetTask                       ✅
SUBMITTED                     ✅
WORKING                       ✅
COMPLETED                     ✅
FAILED                        ✅
REJECTED                      ✅
Artifact result               ✅
Memory Task Store             ✅

CANCELED state recognition    ✅
CancelTask                    ❌
ListTasks                     ❌
INPUT_REQUIRED                ❌
AUTH_REQUIRED                 ❌
ActiveRecord Task Store       ❌
ActiveJob execution           ❌
Streaming / Subscribe         ❌
```

## 18. Quick Start Design (Step 14)

詳細は [Quick Start Design](quick-start.md) を正本とする。Step 14は設計として完了し、実装・実行検証は未着手。

確定事項:

- 汎用的なEcho Agentを導入例にする。
- 中間成功はAgent Card取得、最終成功は `TASK_STATE_COMPLETED` と `Echo: Hello` のArtifact。
- Generatorはinitializer / Agent scaffoldのみ。Handlerを自動生成せず、存在しないHandlerを参照しない。
- A2A v1.0 JSON-RPCでは `SendMessage` / `GetTask`、`ROLE_USER`、直接的なText Part、`A2A-Version: 1.0` を使用する。
- 標準リクエストにSkill ID指定はない。Skillが1つなら自動dispatch、複数ならアプリ側Routerを必須とする。
- Router DSLは `router Shopping::AgentRouter`、呼び出しは `.call(message:, context:, skills:)`。
- HandlerへはSDK非依存Ruby Hashを渡す。Message schema keyはSymbol、roleは `:user` / `:agent`。
- Handler contextは `task_id` / `context_id` / 選択後の内部 `skill_id`。
- 専用のPublic Message / Context / TextPartクラスは作らない。
- Agent未登録・不完全設定を理由にRails起動を壊さず、A2A利用時に検証する。
- 設定不備はGem Errorとしてログへ記録し、不正Agent Cardを公開しない。
- Handler内部例外は詳細をRails loggerへ記録し、外部にはgenericなFAILED Taskを返す。

Routerの `skills` collection詳細・routing失敗のwire mapping・設定エラーのJSON-RPC envelope/codeは、実装時のSDK互換性確認で確定・テストする。
