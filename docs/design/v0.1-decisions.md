# a2a-rails v0.1 Design Decisions

## 1. Project Goal

a2a-rails は、

> Railsアプリを、RailsらしくA2A Agentとして公開するためのRails Integration Gem

を目指す。

English:

> Expose Rails applications as A2A agents using Rails-native conventions.

---

## 2. Positioning

a2a-rails は A2A Protocol SDK ではない。

```text
A2A Protocol
     ↓
Ruby A2A SDK
     ↓
a2a-rails
     ↓
Rails Application
     ↓
Business Logic
```

a2a-rails 自身では Protocol を再実装しない。

---

## 3. Ruby A2A SDK

現時点では、下層SDKの第一候補として `agent2agent` を検討する。

理由:

- A2A Server 対応
- A2A Client 対応
- JSON-RPC 対応
- HTTP+JSON 対応
- Rack / Rails から利用可能
- Task lifecycle を扱える
- Streaming にも対応可能

`simple_a2a` も候補だが、v0.1では `agent2agent` を優先して検討する。

ただし、a2a-rails の Public API を `agent2agent` 固有APIへ依存させない。

---

## 4. SDK Boundary

構造は以下を基本とする。

```text
Rails Application
      ↓
A2A::Rails::Agent
Skill
Handler
      ↓
Dispatcher
      ↓
Internal Protocol Boundary
      ↓
Agent2Agent Adapter
      ↓
agent2agent
      ↓
A2A Protocol
```

Adapter は v0.1 から内部的には存在してもよいが、Public API として公開しない。

例えば以下のような設定は、v0.1ではまだ提供しない。

```ruby
config.protocol_adapter = :agent2agent
```

将来、Official Ruby SDK などが登場した場合に交換可能な構造だけ確保する。

---

## 5. Public API Policy

Rails開発者にはProtocol固有コードをできるだけ見せない。

v0.1 の基本API:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

Handler:

```ruby
class Shopping::SearchProducts
  def self.call(message:, context:)
    # Rails business logic
  end
end
```

Public APIへ以下を漏らさない。

```text
Rack env
A2A Protocol Schema
JSON-RPC implementation
Transport implementation
SDK固有Error
SDK固有Request object
```

---

## 6. Terminology

A2A標準用語を可能な限りそのまま使う。

### Agent

A2Aとして外部公開されるAgent。

a2a-railsでは:

```ruby
A2A::Rails::Agent
```

### Agent Card

Agentの情報・Skill・接続方法などを公開するA2A標準情報。

Rails側のAgent定義から生成する。

### Skill

Agentが外部に提供する能力。

例:

```ruby
skill :search_products
```

### Message

Agent間でやり取りするA2A Message。

独自Message classは原則作らない。

### Task

A2A標準のTask。

独自Task lifecycleを作らず、A2A標準の状態を使用する。

### Artifact

Taskによって生成された成果物。

### Handler

a2a-rails側の概念。

A2A SkillとRails Business Logicを接続する。

```text
A2A Skill
    ↓
Handler
    ↓
Rails Service
```

---

## 7. Core Architecture

```text
Remote A2A Client
       │
       ▼
Ruby A2A SDK
       │
       ▼
Protocol Adapter
       │
       ▼
Dispatcher
       │
       ▼
Skill
       │
       ▼
Handler
       │
       ▼
Rails Business Logic
```

a2a-rails の中心的責務は、

> A2A SkillをRails Business Logicへdispatchすること

とする。

## 8. v0.1 Scope

### Included

- Rails integration
- `A2A::Rails::Agent`
- Skill DSL
- Handler dispatch
- Agent Card generation
- `/.well-known/agent-card.json`
- A2A request受付
- 最小限のTask lifecycle
- Rails Engine / Routes
- Configuration
- Generator
- Rails Logging
- Test support

### Not Included

- A2A Client
- 独自A2A Protocol
- 独自Transport
- gRPC
- Push Notification
- BiDi Streaming
- Human-in-the-loop
- Agent Registry service
- Agent Marketplace
- OAuth Server
- Authorization Engine
- ActingFor integration
- Admin UI
- LLM Agent Framework
- Orchestration Framework

---

## 9. Server First

v0.1はServer Sideに集中する。

```text
Remote A2A Agent
       ↓
a2a-rails
       ↓
Rails Application
```

Client機能はv0.1では対象外。

最初の成功条件は、

```text
1. GemをRailsへ追加
2. Agent / Skillを書く
3. 他のA2A Agentから呼び出せる
```

とする。

---

## 10. Streaming

v0.1ではNon-Streaming Serverを優先する。

```text
v0.1

✅ 基本Request / Response
✅ Message処理
✅ Task処理

❌ SSE Streaming
❌ Subscribe
❌ BiDi Streaming
```

理由:

- 既存Railsアプリへの導入を簡単にする
- Web Server構成への依存を増やさない
- v0.1のScopeを小さく保つ

Streamingは後続バージョンで検討する。

---

## 11. Task Persistence

Task persistenceはRails Integration側で扱えるようにする。

ただし、ActiveRecord / ActiveJobをv0.1の必須要件にはしない。

将来的には:

```text
A2A Task
   ↓
a2a-rails Task Store
   ↓
ActiveRecord

A2A Task
   ↓
ActiveJob
   ↓
Rails Service
```

のようなIntegrationを検討する。

---

## 12. ActingFor

a2a-railsとActingForは別Gemとして維持する。

```text
a2a-rails
    ↓
Agent Communication

ActingFor
    ↓
Delegated Authorization
```

a2a-rails本体からActingForへ依存しない。

将来的に必要であればIntegration Gemを検討する。

例:

```text
acting_for-a2a
```

---

## 13. Design Principles

新機能を追加するときは以下を確認する。

1. v0.1に本当に必要か
2. Ruby A2A SDK側の責務ではないか
3. Rails Integration Layerの責務か
4. RailsらしいAPIか
5. A2A標準と衝突しないか
6. SDK固有実装がPublic APIへ漏れていないか
7. 将来SDKを交換できるか
8. 過剰設計になっていないか

最重要ルール:

> Protocolを再発明しない。

> Rails Integrationに集中する。

---

## 14. Current Architecture Decision

現時点の基本方針:

```text
A2A Standard
     ↓
Ruby A2A SDK
     ↓
Thin Protocol Boundary
     ↓
a2a-rails Dispatcher
     ↓
Rails Handler
     ↓
Rails Business Logic
```

v0.1では `agent2agent` をRuby A2A SDKの第一候補として検討する。

ただし、Public APIからSDK固有実装を隠し、将来のSDK変更に備える。

---

## 15. Public API Design

### Agent DSL

Railsアプリ側は `A2A::Rails::Agent` を継承して公開Agentを定義する。

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

`ShoppingAgent` は用途例であり、Gemは特定ドメイン専用ではない。

### Skill DSL

SkillはSymbolで宣言する。

```ruby
skill :search_products,
  description: "Search products",
  tags: %w[shopping search],
  handler: Shopping::SearchProducts
```

基本方針:

- Skill ID はSymbolから生成する
- Skill name はIDから自動生成し、必要なら明示的に上書き可能にする
- `description` は必須
- `tags` は必須
- `handler` は必須
- `examples` などのA2A標準オプション情報は必要に応じて指定可能にする
- Protocol固有の定型情報は可能な限りGem側で補完する

### Handler Interface

標準Handler Interface:

```ruby
class Shopping::SearchProducts
  def self.call(message:, context:)
    # Rails business logic
  end
end
```

方針:

- SDK固有Request objectをHandlerへ渡さない
- Rack envをHandlerへ渡さない
- `message` と `context` をRails側の安定した境界として扱う
- HandlerはRails Service / Modelなど既存Business Logicを呼び出す
- Handlerの戻り値からA2AのMessage / Task / Artifactへの変換はGem内部で扱う

### Agent Registration

v0.1では **1 Rails Application = 1 Public A2A Agent** とする。

公開Agentはinitializerで明示登録する。

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
end
```

方針:

- Agentクラスを作っただけでは外部公開しない
- 登録したAgentのみ公開する
- reload / autoloadを考慮し、Agentはクラス名文字列で登録できるようにする
- 複数Agent公開はv0.1の対象外とし、必要なら後続バージョンで検討する

推奨配置:

```text
app/
└── agents/
    └── shopping_agent.rb
```

### Routing

v0.1では標準RouteをGem側で提供する。

```text
GET  /.well-known/agent-card.json
POST /a2a
```

方針:

- 利用者が通常 `routes.rb` にmountを書く必要はない
- v0.1では標準Routeを固定する
- Agent Card endpointとA2A request endpointをGem内部のRails Engine / Routesで提供する

### Configuration API

v0.1のConfiguration APIは小さく保つ。

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
  config.public_base_url = ENV["A2A_PUBLIC_BASE_URL"]
  config.logger = Rails.logger
end
```

設定:

- `agent`: 必須。公開するAgentクラス名
- `public_base_url`: 任意。外部公開URLを自動判定できない場合に指定
- `logger`: 任意。デフォルトは `Rails.logger`

v0.1では以下をPublic Configurationに出さない。

```ruby
config.protocol_adapter = :agent2agent
config.transport = :json_rpc
config.streaming = false
config.sdk_options = {}
```

Protocol / SDK / Transport固有設定は内部実装として隠す。

### Error Handling API

Protocol固有ErrorをRails開発者へ直接扱わせない。

基本分類:

```text
Invalid A2A Request
        ↓
SDK / Protocol Adapter
        ↓
A2A standard error

Unexpected Handler Exception
        ↓
a2a-rails
        ↓
Rails logger
        ↓
Internal error

Business Logic Failure
        ↓
Task lifecycle
        ↓
Step 11で設計
```

Gem自身の設定・実装エラーには共通基底Errorを持つ。

```text
A2A::Rails::Error
A2A::Rails::ConfigurationError
A2A::Rails::UnknownSkillError
A2A::Rails::InvalidHandlerError
```

A2A ProtocolのJSON-RPC errorやSDK固有ErrorはPublic APIへ露出させない。

## 16. Agent Card Design

v0.1では、Rails側のAgent / Skill DSLからA2A Agent Cardを自動生成する。

設計原則:

> Rails開発者はAgentの意味的な情報を書く。

> Protocol固有の定型情報はGem側で補完する。

### Agent Card Endpoint

```text
GET /.well-known/agent-card.json
```

A2A request endpoint:

```text
POST /a2a
```

### Public Endpoint URL

Agent Cardの `supportedInterfaces[].url` は以下の優先順位で生成する。

```text
1. config.public_base_url
        ↓ 未指定の場合
2. request.base_url
        ↓
3. /a2a を付与
```

例:

```ruby
A2A::Rails.configure do |config|
  config.public_base_url = "https://example.com"
end
```

生成結果:

```text
https://example.com/a2a
```

`public_base_url` には `/a2a` を含めない。

Reverse Proxy / Load Balancerなどにより外部URLをRequestから正しく判定できない場合は、`public_base_url` の明示設定を推奨する。

### Supported Interface

v0.1ではNon-Streaming JSON-RPC Serverとして公開する。

```json
{
  "supportedInterfaces": [
    {
      "url": "https://example.com/a2a",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ]
}
```

Rails開発者には `protocolBinding` / `protocolVersion` を通常設定させない。

### Agent Field Mapping

Rails DSL:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"
end
```

Mapping:

```text
name        → Agent Card name
description → Agent Card description
version     → Agent Card version
```

Agent側では以下を必須とする。

- `name`: 空でないString
- `description`: 空でないString
- `version`: 空でないString
- `skills`: 1件以上

### Skill Mapping

Rails DSL:

```ruby
skill :search_products,
  description: "Search products",
  tags: %w[shopping search],
  examples: ["Search for a laptop under $1000"],
  handler: Shopping::SearchProducts
```

Mapping:

```text
skill Symbol  → skills[].id
name          → skills[].name
description   → skills[].description
tags          → skills[].tags
examples      → skills[].examples
input_modes   → skills[].inputModes
output_modes  → skills[].outputModes
handler       → Agent Cardには出力しない
```

Skill `name` を省略した場合、IDから自動生成する。

```text
search_products
      ↓
Search Products
```

必要なら明示的に上書き可能とする。

```ruby
skill :search_products,
  name: "Product Search",
  description: "Search products",
  tags: %w[shopping search],
  handler: Shopping::SearchProducts
```

Skill側のValidation:

- IDはSymbolで宣言する
- IDはAgent内で重複不可
- `description` は必須・空文字不可
- `tags` は必須・1件以上
- `handler` は必須
- Handlerは `.call` に応答すること
- `examples` は任意の `Array<String>`
- `input_modes` は任意の `Array<String>`
- `output_modes` は任意の `Array<String>`

### Default Input / Output Modes

v0.1のAgent全体のデフォルト:

```json
{
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"]
}
```

Agent DSLではv0.1時点でこの設定を公開しない。

特殊なSkillのみ必要に応じて上書き可能とする。

```ruby
skill :analyze_image,
  description: "Analyze an image",
  tags: %w[image analysis],
  input_modes: ["image/png", "image/jpeg"],
  output_modes: ["text/plain"],
  handler: Image::Analyze
```

### Capabilities

v0.1では以下をサポートしない。

```text
streaming          → unsupported
pushNotifications  → unsupported
extendedAgentCard  → unsupported
extensions         → none
```

概念上のAgent Card:

```json
{
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false
  }
}
```

SDKのserializationにより `false` field自体が省略されてもよい。

Public APIとしてはJSON上の `false` の存在ではなく、該当機能がunsupportedであることを保証する。

Rails開発者には以下のような設定を提供しない。

```ruby
config.streaming = false
config.push_notifications = false
config.extended_agent_card = false
```

実装されていないCapabilityを設定だけで有効化できないようにする。

### Optional Agent Card Fields

v0.1では以下を公開しない。

```text
provider
iconUrl
documentationUrl
securitySchemes
securityRequirements
signatures
extensions
```

理由:

- 最小Server実装に必須ではない
- Security / Authenticationは別設計として扱う
- Agent Card署名はv0.1 Scopeを超える
- 表示用metadataは後から互換性を保って追加しやすい

### Validation Timing

Validationは2段階を基本とする。

```text
Agent / Skill DSL定義
       ↓
基本Validation
       ↓
登録Agentをresolve
       ↓
最終Validation
       ↓
Agent Card生成
```

`config.agent` はautoload / reloadを考慮してクラス名文字列で登録可能とするため、initializer実行時だけですべてを確定させない。

最終的なAgent Card生成前に登録Agentをresolveし、定義全体を検証する。

### Invalid Agent Card

Validationに失敗したAgent Cardは外部公開しない。

```text
GET /.well-known/agent-card.json
        ↓
Validation failure
        ↓
500 Internal Server Error
        +
Rails logger
```

内部のRuby class名・stack trace・SDK固有Errorなどを外部レスポンスへ漏らさない。

Gem側の設定・定義エラーには既存Error hierarchyを利用する。

```text
A2A::Rails::Error
├── A2A::Rails::ConfigurationError
├── A2A::Rails::UnknownSkillError
└── A2A::Rails::InvalidHandlerError
```

Agent / Skill validation専用Error classをv0.1で過剰に増やさない。

### Final v0.1 Agent Card Example

Rails側:

```ruby
class ShoppingAgent < A2A::Rails::Agent
  name "Shopping Agent"
  description "Search and purchase products"
  version "1.0"

  skill :search_products,
    description: "Search products",
    tags: %w[shopping search],
    handler: Shopping::SearchProducts
end
```

Configuration:

```ruby
A2A::Rails.configure do |config|
  config.agent = "ShoppingAgent"
  config.public_base_url = "https://example.com"
end
```

概念上生成されるAgent Card:

```json
{
  "name": "Shopping Agent",
  "description": "Search and purchase products",
  "version": "1.0",
  "supportedInterfaces": [
    {
      "url": "https://example.com/a2a",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ],
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "search_products",
      "name": "Search Products",
      "description": "Search products",
      "tags": ["shopping", "search"]
    }
  ]
}
```

重要:

- `handler` はAgent Cardへ出力しない
- Protocol / Transport固有の定型情報はGem側で補完する
- v0.1ではA2A標準に必要な最小情報だけを公開する
- 特定ドメイン向けのAgent設計にはしない
